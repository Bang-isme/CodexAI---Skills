# v18.1.0 Product Usability Implementation Plan

> **For agentic workers:** Use the native in-session execution method. Keep the host adapters at equal prominence and do not publish this package.

**Goal:** Make the pack easier to evaluate and install, and make its default project outputs smaller and more predictable.

**Architecture:** Keep current package and project artifact paths, improve the installer contract and role-doc defaults, and separate the short product entry page from installation and technical reference material. Add executable checks around each behavior and align every version-bearing manifest at the end.

**Tech Stack:** Markdown, JSON, Python standard library `unittest`, existing local validation and release scripts.

**Spec:** `docs/superpowers/specs/2026-10-02-v18.1-onboarding-and-artifacts-design.md`

## Global Constraints

- Keep Codex, Claude Code, Cursor, and Antigravity equally visible.
- Do not silently install every host or write project files during user-scope installation.
- Do not require GitHub CLI for core skill use.
- Preserve established `.codex/` artifact paths; create only task-relevant folders.
- Do not claim visual quality or live host behavior that was not verified.
- Use the Python `unittest` suite and existing Node test runner; do not add a test dependency.

## Review Focus

- Running the installer from an unrelated directory with user scope must not create bridge files there; pin with a temp-directory installer test.
- Omitting an install host must not install all adapters; pin argument resolution behavior.
- Initializing role docs with no roles must not create 33 role files; pin exact files and idempotence.
- Existing role-specific docs must not be overwritten when adding another role; pin selective initialization.
- Release archives must not include planning documents; pin the archive file filter.
